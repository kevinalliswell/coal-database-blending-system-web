# CBOS 2.0 煤质基准契约

本契约取代 1.x 的“共享基准字段 + 未确认试算”规则。所有计算先经过逐指标准入；不按煤名推断，不猜测元数据。

## 存储与身份

- 主档保存煤名、类型；批次保存到货编号、供方、日期；化验修订不可变。
- `raw` 中每项保存 `value/unit/basis`，热值附 `heat_type`，氢附 `hydrogen_includes_moisture`。
- `null` 或缺失表示未知，数值 0 是有效观测。空白不被补零。
- 指标采用值在计算时派生，不覆盖原值。差减固定碳保留派生来源。
- 报价属于修订原始数据；计算结果保存该报价及换算值快照。

## 系统口径

默认 `ratio_basis=ar`、`heat_type=net_v`、`heat_unit=MJ/kg`。可改为干基配比和恒容高位；设置版本单调递增，变更基准/热值类型必须重新确认约束。前端显示单位可变，混煤 API 和算法热值保持 kcal/kg，单位因子 `1 kcal/kg = 0.0041868 MJ/kg`。

## 转换与准入

公式、依赖字段和适用范围见 [换算规范](ASSAY_CONVERSION.md)。`evaluate_assay` 分别返回 blending / theory 的 `eligible,issues,values,trace`。标准错误字段为 `field,code,message`。

工业分析统一到干基检查 A+V+FC 闭合（±0.5 个百分点）。固定碳差减不减硫，不等于元素碳。不得反推水分，不跨批次借值。缺少氮、HGI、燃尽率不阻止不需要这些指标的计算。

恒压或定义未知的热值可以保留，但不进入热值优化。高低位转换需要氢；同一恒容低位热值换基只检查所需水分。

## 计算与历史

请求通过化验修订 ID 定位，每个批次一次一份修订。后端校验设置版本、归档状态、数据准入和比例边界。数学无解与数据错误是不同状态。

新结果 `input_snapshot.schema_version=2`，包含原值、采用值、trace、公式版本、修订身份、系统设置和操作者。旧历史按原快照读取，未知字段保持未记录。
