# CBOS 2.0 用户手册

CBOS 管理喷煤煤质数据，并按统一质量口径计算混配方案。网页版与 Windows 离线版功能一致；各部署的账号和数据独立，不自动同步。

## 1. 首次使用与账号

Windows 第一次启动在本机创建管理员，没有默认密码。网页版由部署管理员先执行 `flask --app wsgi initialize`，再执行 `flask --app wsgi users create-admin --username admin`，按提示输入密码。密码至少 12 位，不要把密码写在命令行参数中。

每次启动桌面程序需要登录。退出或修改密码后重新登录。管理员可以创建用户、重置密码和停用账号；不能停用或降级最后一个有效管理员。账号恢复见升级说明。切换账号会清理查询缓存，混煤草稿和主题按用户隔离。

| 操作 | 管理员 | 数据维护员 | 计算员 | 只读 |
| --- | --- | --- | --- | --- |
| 查看与导出数据、历史 | 是 | 是 | 是 | 是 |
| 录入、导入、新增修订、归档 | 是 | 是 | 否 | 否 |
| 执行计算、保存结果 | 是 | 否 | 是 | 否 |
| 管理用户与系统设置 | 是 | 否 | 否 | 否 |

## 2. 煤种、批次与化验修订

在“煤种数据库”建立煤种主档，再建立到货批次，最后录入化验报告。煤种名称用于识别资料，名称中的“分析基”等文字不会改变数据基准。

不同到货批次分别保存，同煤种多个批次可以同时混配。化验更正时新增修订，旧修订保留。一次计算中同一批次只能选择一份修订。归档使记录不能再参与新计算，原记录与历史快照保留。

不完整记录可以保存。空白表示缺失，0 表示实际测得为零，两者不同。工业分析不闭合的记录也可存档待核对，但不能用于受影响的计算。无需人工审批，数据条件满足即可使用。

## 3. 按报告原样录入

每项指标分别填写数值、单位和基准。不要因为系统默认使用收到基，就把报告中的干基数值直接标成收到基。

常见报告组合示例（教学数据，不代表某一实煤）：

| 指标 | 原始值 | 单位 | 基准 / 类型 |
| --- | --- | --- | --- |
| 全水分 Mt | 10 | % | 收到基 ar |
| 空干基水分 Mad | 2 | % | 空干基 ad |
| 灰分 Ad | 12 | % | 干基 d |
| 挥发分 Vdaf | 20 | % | 干燥无灰基 daf |
| 全硫 St,d | 0.6 | % | 干基 d |
| 热值 Qnet,v,ar | 26 | MJ/kg | 收到基、恒容低位 |
| 报价 | 800 | 元/吨 | 按收到吨计价 |

固定碳留空时，可以由工业分析按差减法派生，来源会标明。上述例子 Vd=17.6%、FCd=70.4%，换到收到基得到灰分 10.8%、挥发分 15.84%、固定碳 63.36%。它们与 Mt=10% 合计 100%。固定碳不是元素碳，理论置换比不能使用它代替元素分析的 C。

氢必须说明数值是否包含水分中的氢。热值需要同时声明单位、基准，以及恒容高位/恒容低位等定义。恒压或定义不明的热值可以存档，但不能用于本期混煤热值计算。

## 4. 表格粘贴与导入

支持 CSV、XLSX 与从电子表格复制的制表符文本。推荐下载系统模板；先预览、确认列映射与缺失的单位/基准，再提交。没有依据时保留“未确认”，不要凭煤名或数值大小猜测。未知列可明确选择忽略。

预览显示每行原值、数据问题和计算可用性。无效数值需要修正；数据缺项可以存档。预览绑定当前账号，30 分钟有效且只能提交一次；有人在预览后修改相同批次时，重新预览后提交。

导入同名煤不会覆盖旧化验记录。同煤种、同批次产生新修订。默认导出保留全部修订（含归档）。模板导出包括原始指标的数值、单位、基准与热值定义；导出是数据交换，不代替完整数据库备份。

## 5. 计算采用值与缺项处理

记录详情将原始化验值和各功能的计算采用值分开展示，并显示换算步骤。

- ad 与 d 互转需要该修订的 Mad；ar 与 d 互转需要该修订的 Mt。
- daf 指标换基需要同一修订的灰分，以及该路径实际需要的水分。
- 高位与低位热值互转需要适用的氢数据；同类恒容低位换基仅按水分路径检查，不额外要求氢。
- 工业分析先换成同一干基检查闭合，容差为 0.5 个百分点；不自动缩放化验值，不据残差反推水分。
- 混煤需要灰分、挥发分、固定碳（允许差减）、全硫、热值及价格。理论置换比需要干基元素 C、H、灰分和灰中 SiO2；缺少价格不影响理论置换比。

不能计算时查看具体原因，例如“缺少全水分”或“热值定义不支持”。补录时创建新修订，不跨批次借用水分或氢。

## 6. 智能混煤

1. 确认页面显示的系统口径：默认收到煤质量配比、收到基恒容低位热值、元/收到吨。
2. 选择至少两个批次的化验修订。不可用记录显示缺项原因。
3. 设置工艺上下限和各批次比例边界，比例单位是百分比。
4. 选择算法参数后求解。服务端再次检查数据、配置版本与比例边界。
5. 对比 Pareto 候选，查看配比与指标，保存的结果可在混煤历史中查看、导出。

线性规划先判断数值可行性并建立最低成本可行起点，NSGA-II 随后搜索成本、热值与工艺偏离程度之间的折中。质量偏离分是模型偏好评分，不是燃烧风险概率。通过数值检查不代表通过现场工艺验证；燃烧相互作用和实际高炉效果不在本模型预测范围。

结果区分数据缺项、转换依赖、数据冲突和数学无可行解。无可行解时调整约束或煤种组合；不能通过试算模式绕过未知基准。

历史保留原始修订、计算采用值、公式版本、报价、设置与操作者快照。后来修改煤名、报价、化验或系统设置不会改写旧结果。旧版本历史缺少的信息显示未记录，不使用当前资料补填。

## 7. 置换比

理论置换比始终使用模型要求的干基元素和灰分、灰中 SiO2。煤的分解耗热、物理耗热、焦炭成分及炉况由用户明确提供。优先填写实测热风焓；只有显式选择工程估算时才按风温估算，并记录来源与模型常量。

实际置换比使用同一炉号、明确前后期间和质量口径的煤比/焦比变化。不填观测数据不能计算。使用修正量时明确填写数值及来源；旧版未经标定的高级修正不再隐式应用。

## 8. 系统设置

管理员可设置系统名称、单位、默认质量基准、恒容热值类型、显示单位、工艺约束模板及算法预设。改变质量基准或热值类型后，必须重新确认约束模板。

已经打开的计算页在设置变化后提示刷新；运行中的计算和历史仍使用提交时的配置。热值显示单位可选 MJ/kg 或 kcal/kg；换单位不会改变热值物理量。

## 9. 备份、恢复与版本

Windows 退出程序后复制整个用户数据目录，包括 `coal_system.db` 与 `.app-secret`。升级数据库前会自动生成 SQLite 一致性备份。恢复时先关闭程序，保存当前目录，再用相同版本兼容的完整备份恢复。卸载不删除用户数据。

Web 停止写入后备份数据库与部署配置；SQLite 在线备份使用 SQLite backup API，不能在有 WAL 写入时只复制主文件。MySQL 使用部署方的一致性备份方案。

“关于”显示系统版本、完整构建提交和运行方式。安装前核对发行资产 SHA-256。Windows 未配置签名证书时安装包为未签名状态，详见同版本安装说明。

进一步阅读：`docs/ASSAY_CONVERSION.md`（公式）、`docs/API_REFERENCE.md`（接口）、`docs/UPGRADE_2.0.md`（升级与恢复）。
