# 混配请求验证修复

重复的煤种ID原先会生成多个独立基因，允许同一煤的合计用量超过其比例上限。优化接口现在先规范化请求，要求至少两个不同的正整数ID；拒绝浮点、布尔、null和重复ID。十进制ID字符串仍受支持，归一化后检查重复；配比约束中的ID采用同一规则。

请求体、constraints、ga_params及ratio_constraints必须为相应对象/数组。已知数值必须有限；计数参数必须为整数；非法输入返回400而不是500或search_failed。

配比边界允许`min == max`以便固定配方。不提供某个已选煤的边界时补全为0–100%，然后再校验总和；不再把部分约束误判成上限不足。未选煤的配比键被拒绝。质量区间也允许相等边界；传入边界与实际默认边界一起校验。

算法规模上限与前端设置范围一致：种群2000、代数10000、线程16；早停最多10000。random_seed为0到2³²−1的整数，convergence_threshold非负且有限；本次仅校验这两个字段，后续求解器PR负责传递和执行。较大规模仍需按服务器性能选择，范围检查不代表计算时间保证。

新增真实Flask/SQLite回归覆盖重复ID、错误形状、非有限数、固定比例、部分边界和数字字符串映射。合法请求保留原有结果结构；原有不合法请求现在明确失败。

公开API文档中的历史`min < max`规则更新为`min <= max`；所有合计检查基于已选煤补齐后的完整约束。已有调用方如发送重复ID、非整数ID、NaN/Infinity或未知配比键，需先修正请求。
