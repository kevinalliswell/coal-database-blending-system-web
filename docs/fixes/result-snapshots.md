# 结果、导出与求解快照

## 修复行为

- 每次提交复制所选煤种、约束与算法配置。编辑任何求解参数后，旧结果从结果区隐藏并明确提示重新求解；复制和导出入口同时消失。请求进行中编辑参数，较晚返回的结果也不会被当作当前结果。新请求失败不恢复旧的绿色可行结果。
- 当前结果图表使用本次求解的约束快照；切换 Pareto 候选后，指标、活跃约束、质量风险、分享内容及 Excel 中的配比保持一致。
- 历史保存失败同时展示通知和持续提示，可继续导出当前结果。
- 配比和质量窗口允许相同上下限，可锁定某个数值。未参与算法的目标热值控件已删除，界面改为显示热值窗口；旧本地设置的 `heat_target` 不再发送。

## API 与历史兼容

`POST /api/optimization` 保留已有字段，并新增顶层 `constraints`（包括默认值的实际约束）和 `input_snapshot`：

| 字段 | 内容 |
|---|---|
| `schema_version` | 快照格式版本，目前为 1 |
| `calculation_mode` | 实际采用的 `verified` 或 `screening` 模式，包含未显式提交时的默认模式 |
| `ratio_basis` | 实际采用的配比质量基准 |
| `data_validation` | 输入一致性检查的状态、范围及 warnings；重放时保留试算用途限制 |
| `coals` | 求解当时的完整 `Coal.to_dict()`，含价格、水分、类型及其后的数据基准扩展 |
| `algorithm_coals` | 实际交给计算器的煤质字段 |
| `algorithm_params` | 完整求解约束参数 |
| `ga_config` | 类型转换、默认补全后的优化器配置，求解开始前复制 |
| `constraints` | 便于界面和报告使用的实际约束，配比为百分数 |

完整响应保存在已有历史 JSON 字段内，无须新增数据库列。之后煤质或价格发生变化不会影响已保存的输入快照。原始请求仍存于 `request_payload`，历史摘要的 `constraints` 存本次实际使用的约束。

报告优先采用快照的约束，再兼容旧响应/历史的顶层 `constraints`。旧记录没有快照时仍可查看、导出；缺少某指标全部边界时显示“未校验”，不再写成“达标”。旧记录不能凭空恢复求解时的煤质。

快照记录软件实际输入和配置，不构成煤质检验数据或工艺安全的额外认证。后续数据基准验证层可在 `coals` 及响应中添加声明，现有快照与导出会保留这些字段。
