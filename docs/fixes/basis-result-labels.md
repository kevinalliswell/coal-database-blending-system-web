# 计算基准与试算结果的用途

> 历史修复记录（CBOS 1.x）：以下模式说明不适用于 2.0 新计算。2.0 已移除 screening/verified 选择，按不可变化验修订换算并执行缺项准入；旧历史的筛选标签继续保留。现行行为见 [基准契约](../DATA_BASIS_CONTRACT.md) 和 [升级说明](../UPGRADE_2.0.md)。

## 选择计算模式

智能混煤默认采用 `verified`（界面“基准一致计算”）。用户需要选择配比质量基准：空气干燥基 `ad`、收到基 `ar` 或干基 `d`。输入的煤质、热值与价格基准由后端一致性检查处理；本版本不自动换算。

尚未确认数据基准时，必须主动选择 `screening`（界面“未确认数据试算”）。该模式可保留 `ratio_basis=unknown`，结果只能用于筛选。已声明但互相冲突的基准仍会被后端拒绝；筛选模式不是忽略所有数据错误的开关。

模式和配比基准一起进入不可变请求快照。改变其中任何一项后，旧结果失效。

## 区分三种结果

| `result.data_validation` | 展示 | 含义 |
|---|---|---|
| `status=verified` | 基准检查通过 | 仅表示输入基准一致与工业分析闭合检查通过，不代表现场工艺验证 |
| `status=unverified` | 基准未确认，仅用于筛选 | 橙色提示并完整展示 warnings；不得直接作为生产方案 |
| 字段缺失 | 基准验证未记录 | 兼容旧历史；不推断为已确认 |

`is_feasible` 仅代表数值约束下的数学可行性。页面不再把它写成“已验证生产方案”；筛选结果的数值指标仍可查看，但会保留用途限制。

请求、响应、历史详情、复制文本和 Excel 均保留这一区分。Excel 新增“数据基准与用途”区，显示配比基准、检查范围和所有 warnings；未确认试算不会输出“推荐用于喷煤配煤”等不符合证据的结论。即使旧后端或演示响应缺少验证元数据，显式 `screening` 请求也不会丢失筛选标签。

## 验证

```sh
python -m pytest tests/test_basis_report_labels.py tests/test_result_snapshots.py -q
cd frontend
node --test tests/blending-result.test.mjs
npm run build
```

报告测试覆盖未确认、基准检查通过、旧历史三种标签；前端测试覆盖模式/基准改变使旧结果失效、响应缺少元数据时的筛选限制，以及导出保持同一限制。

浏览器验收后将界面/报表中的“质量风险”统一标为“质量偏离分”，说明其为窗口偏好评分，不是燃烧风险概率；缺失基准提示使用中文字段名称。
